Fase 1: Apertura (Activación y Contextualización)

El Principio de Mínimo Privilegio (PoLP)

Uno de los errores más graves en la industria es conectar las aplicaciones web utilizando el superusuario root. Si la aplicación sufre una vulnerabilidad de inyección SQL, el atacante obtiene control total para borrar todas las bases de datos o crear usuarios administradores clandestinos.

Cada rol y usuario debe contar estrictamente con los permisos necesarios para su función operativa (ej. solo SELECT e INSERT para cajeros).

Preguntas Diagnósticas

  1. ¿Por qué en MySQL el usuario se identifica mediante 'usuario'@'host' (ej. 'app_user'@'localhost' vs 'app_user'@'%')?
  2. ¿Cuál es la diferencia operativa entre un Respaldo Completo (Full Dump) y un Respaldo Incremental basado en Binary Logs (Binlog)?
  3. ¿Por qué es indispensable ejecutar el comando FLUSH PRIVILEGES; tras modificar tablas del sistema en motores relacionales?

Fase 2: Desarrollo Conceptual (Usuarios, Roles y Backups)

Control de Accesos (DCL)
  • GRANT: Concede permisos específicos sobre tablas, vistas o procedimientos.
  • REVOKE: Retira privilegios asignados previamente a un usuario o rol.
  • ROLES: Agrupaciones de privilegios (ej. rol_auditor) asignables a múltiples usuarios.
Estrategias de Respaldo
  • Full Backup: Copia completa de todas las tablas y esquemas (`mysqldump`).
  • Incremental Backup: Guarda solo los cambios ocurridos desde el último respaldo.
  • Restauración: Procedimiento de contingencia para reconstruir el servidor ante desastres.

Fase 3: Scripts de Seguridad y Respaldo CLI

-- 1. CREACIÓN DE USUARIO Y ASIGNACIÓN DE PRIVILEGIOS GRANULARES CREATE USER 'docente_user'@'localhost' IDENTIFIED BY 'PassSegura$2026';
GRANT SELECT, INSERT, UPDATE ON conalep_escolar.alumnos TO 'docente_user'@'localhost';
GRANT SELECT ON conalep_escolar.v_directorio_docente TO 'docente_user'@'localhost';
FLUSH PRIVILEGES;
-- 2. GESTIÓN DE ROLES DE SEGURIDAD CREATE ROLE 'rol_caja';
GRANT SELECT, INSERT ON conalep_escolar.pagos TO 'rol_caja';
GRANT 'rol_caja' TO 'docente_user'@'localhost';
SET DEFAULT ROLE ALL TO 'docente_user'@'localhost';
# 3. COMANDO DE RESPALDO COMPLETO EN TERMINAL (MYSQLDUMP) mysqldump -u root -p --routines --triggers --databases conalep_escolar > respaldo_conalep_2026.sql

# 4. RESTAURACIÓN EN CASO DE CONTINGENCIA
mysql -u root -p conalep_escolar < respaldo_conalep_2026.sql

Problemario de Seguridad, Roles y Respaldos (40% Firmas)

10 Ejercicios
1. Creación de 3 Cuentas con Diferentes Hosts: Crea 'admin'@'localhost', 'app'@'10.0.0.5' y 'reportes'@'%'.
2. Asignación Granular a Nivel de Columna: Escribe el comando para permitir a un usuario actualizar únicamente la columna telefono en la tabla alumnos.
3. Revocación de Privilegios con Revoke: Retira el permiso de DELETE sobre todas las tablas de la base de datos al usuario practicante.
4. Implementación de Roles Corporativos: Crea el rol rol_recursos_humanos, asigna permisos a las tablas de nómina y asígnalo a 2 usuarios.
5. Inspección de Privilegios con Show Grants: Interpreta la salida del comando SHOW GRANTS FOR 'docente_user'@'localhost';.
6. Respaldo de Tablas Específicas con Mysqldump: Escribe el comando para respaldar únicamente las tablas carreras y alumnos en un archivo .sql.
7. Respaldo sin Datos (Solo Estructura DDL): Utiliza el parámetro --no-data de mysqldump para exportar solo el esquema.
8. Simulación de Recuperación ante Desastres (Disaster Recovery): Borra deliberadamente una base de datos de prueba y restáurala íntegramente desde el archivo de backup.
9. Cifrado de Contraseñas y Conexiones SSL/TLS: Explica cómo configurar el flag REQUIRE SSL en un usuario para forzar tráfico cifrado.
10. Práctica Integradora Final de Seguridad (Evidencia AE 3.2.1): Presenta la auditoría de seguridad y script de backup para el 10% SAE.
