Fase 1: Apertura (Activación y Contextualización)

Caso Real: Pérdida de Dinero en Transferencia Interbancaria

Durante una transferencia bancaria de $5,000 pesos de la Cuenta A a la Cuenta B, el servidor descuenta los $5,000 de la Cuenta A, pero un corte de energía ocurre antes de acreditar el dinero a la Cuenta B. Sin transacciones, los $5,000 desaparecen del sistema financiero.

Gracias a la propiedad de Atomicidad (ACID), la base de datos detecta que la transacción no finalizó y ejecuta un ROLLBACK automático, devolviendo el saldo intacto a la Cuenta A.

Preguntas Diagnósticas

  1. ¿Qué significa cada una de las 4 letras del acrónimo ACID?
  2. ¿Qué es una Lectura Sucia (Dirty Read) y cómo el nivel de aislamiento READ COMMITTED la previene?
  3. ¿En qué consiste el Protocolo de Bloqueo en Dos Fases (2PL) (Fase de Crecimiento y Fase de Encogimiento)?

Fase 2: Desarrollo Conceptual (Propiedades ACID y Bloqueo 2PL)

Propiedades ACID
  • Atomicidad: "Todo o nada". Todas las sentencias se completan o se deshacen con ROLLBACK.
  • Consistencia: La BD pasa de un estado válido a otro cumpliendo todas las restricciones.
  • Aislamiento: Las transacciones concurrentes operan como si estuvieran en serie.
  • Durabilidad: Un COMMIT exitoso es permanente en el disco.
Bloqueos y Protocolo 2PL
  • Shared Lock (Lectura): Múltiples transacciones pueden leer pero ninguna modificar.
  • Exclusive Lock (Escritura): Solo una transacción tiene acceso exclusivo de lectura/escritura.
  • Fase Creciente 2PL: Adquiere todos los bloqueos necesarios sin liberar ninguno.
  • Fase Menguante 2PL: Libera bloqueos progresivamente tras el COMMIT sin solicitar nuevos.

Fase 3: Script Transaccional en MySQL / InnoDB

-- 1. INICIO DE TRANSACCIÓN ATÓMICA CON CONTROL DE ERRORES START TRANSACTION;

-- Descontar de cuenta origen (Bloqueo Exclusivo)
UPDATE cuentas SET saldo = saldo - 5000 WHERE id_cuenta = 101;

-- Acreditar en cuenta destino
UPDATE cuentas SET saldo = saldo + 5000 WHERE id_cuenta = 202;

-- Registrar auditoría
INSERT INTO transferencias_log (cuenta_origen, cuenta_destino, monto, fecha)
VALUES (101, 202, 5000.00, NOW());

COMMIT; -- Consolida cambios permanentes en disco
-- 2. CASO DE ROLLBACK ANTE FALLA O SALDO INSUFICIENTE START TRANSACTION;
UPDATE cuentas SET saldo = saldo - 20000 WHERE id_cuenta = 101;
-- Se detecta saldo negativo
ROLLBACK; -- Deshace todas las operaciones y libera bloqueos

Problemario de Transacciones y Concurrencia (40% Firmas)

10 Ejercicios
1. Matriz de Propiedades ACID: Elabora una tabla con 4 columnas explicando el significado de cada propiedad, el comando SQL que la respalda y el riesgo de omitirla.
2. Script Transaccional de Venta de Boletos: Modela la compra de boletos de cine asegurando que dos usuarios no compren el mismo asiento al mismo milisegundo con SELECT ... FOR UPDATE.
3. Uso de Puntos de Guardado (SAVEPOINT): Escribe una transacción que use SAVEPOINT sp1; y ejecute ROLLBACK TO sp1; sin cancelar toda la transacción.
4. Análisis de Lectura Sucia (Dirty Read): Modela un cronograma temporal de dos transacciones concurrentes demostrando qué es una lectura sucia.
5. Niveles de Aislamiento en MySQL: Explica las diferencias entre READ COMMITTED y REPEATABLE READ (predeterminado en InnoDB).
6. Detección y Resolución de Deadlocks (Interbloqueos): ¿Cómo detecta el motor InnoDB un ciclo de bloqueo mortal y cuál transacción elige como víctima?
7. Protocolo de Bloqueo en Dos Fases (2PL): Dibuja la curva temporal con la Fase de Crecimiento (adquisición) y la Fase de Encogimiento (liberación).
8. Bloqueo de Tablas vs Bloqueo de Filas: Compara el rendimiento de LOCK TABLES frente al bloqueo a nivel de registro (Row-level Locking) de InnoDB.
9. Desactivación de Autocommit: Explica el impacto de ejecutar SET autocommit = 0; en la sesión de base de datos.
10. Práctica Transaccional de Laboratorio (Evidencia AE 3.1.1): Presenta un script transaccional con manejo de errores y bloqueos concurrentes para el 10% SAE.
