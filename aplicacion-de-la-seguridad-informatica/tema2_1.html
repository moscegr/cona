Fase 1: Apertura (Activación y Reto Provocador)

Caso Real: Escaneo de Puertos y Ataques de Botnets Automatizadas

HackLab #03

En cuanto un servidor Linux con IP pública se enciende en la nube, recibe un promedio de 30 intentos de escaneo y fuerza bruta por minuto en el puerto SSH (22). Si la política del firewall está configurada en ACCEPT por omisión o el puerto 22 está abierto sin rate limiting, el servidor será vulnerado e integrado a una red de botnets en menos de 2 horas.

🔥 Regla de Oro Blue Team: "Política por Defecto DROP: Todo lo que no esté explícitamente permitido, está terminantemente PROHIBIDO."

Fase 2: Desarrollo Conceptual (Tablas iptables, DMZ y Túneles VPN)

Cadenas de iptables

INPUT: Tráfico dirigido al propio host.
FORWARD: Tráfico enrutado a través del firewall (DMZ/LAN).
OUTPUT: Tráfico originado por el firewall.

Arquitectura DMZ

Aísla servidores Web (80/443) y DNS (53). Si el servidor web es comprometido, el atacante no puede saltar a la base de datos de la LAN interna.

VPNs & 802.1X RADIUS

Cifrado de túnel AES-256 (IPsec/OpenVPN) y autenticación de puertos de switch mediante certificados y credenciales de usuario centralizadas.

Fase 3: Script de Hardening Perimetral en Linux Bash

[SCRIPT BASH: CONFIGURACIÓN SEGURA DE FIREWALL IPTABLES]
#!/bin/bash
# 1. Limpiar todas las reglas previas
iptables -F && iptables -X && iptables -t nat -F

# 2. Establecer Política por Defecto DROP (Bloqueo Total)
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT

# 3. Permitir Loopback y Conexiones Establecidas / Relacionadas
iptables -A INPUT -i lo -j ACCEPT
iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# 4. Permitir SSH (Puerto 22) con Protección Anti-Fuerza Bruta
iptables -A INPUT -p tcp --dport 22 -m state --state NEW -m recent --set --name SSH
iptables -A INPUT -p tcp --dport 22 -m state --state NEW -m recent --update --seconds 60 --hitcount 4 -j DROP
iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# 5. Permitir Servidor Web Seguro (80 y 443)
iptables -A INPUT -p tcp -m multiport --dports 80,443 -j ACCEPT
echo "[+] Firewall iptables perimetral configurado y blindado."

Bitácora de Defensa Perimetral (40% Firmas)

10 Retos
Reto 1 (Regla de Bloqueo de Ping ICMP): Escribe la regla de iptables para bloquear las respuestas a paquetes ICMP Echo Request y prevenir el mapeo de red con ping.
Reto 2 (Aislamiento de Servidor en DMZ): Diseña las reglas de la cadena FORWARD para permitir tráfico de Internet al servidor Web en la DMZ (puerto 443), pero prohibir el tráfico de la DMZ a la LAN.
Reto 3 (Port Forwarding con NAT): Configura una regla de PREROUTING en iptables para redirigir peticiones públicas del puerto 8080 hacia el puerto 80 interno.
Reto 4 (Mitigación de Ataques SYN Flood): Escribe una regla de iptables con el módulo limit para limitar las conexiones TCP SYN a máximo 10 por segundo con ráfaga de 20.
Reto 5 (Bloqueo de Puertos Peligrosos de Windows): Diseña la lista de bloqueo perimetral para los puertos NetBIOS (137, 138, 139) y SMB (445) para mitigar propagación de ransomware.
Reto 6 (Configuración de Túnel OpenVPN con Certificados): Diseña el archivo de configuración client.ovpn utilizando certificados TLS/SSL y cifrado AES-256-GCM.
Reto 7 (Implementación de Port Knocking): Modela una secuencia secreta de paquetes a los puertos 7000, 8000 y 9000 para abrir dinámicamente el puerto SSH solo a quien conozca la combinación.
Reto 8 (Persistencia de Reglas con iptables-persistent): Documenta el procedimiento para guardar reglas en /etc/iptables/rules.v4 y asegurar que se carguen al reiniciar el sistema.
Reto 9 (Auditoría de Reglas con Nmap Externo): Comprueba la efectividad de las reglas ejecutando nmap -sS -p- IP_FIREWALL desde una máquina externa verificando puertos filtrados.
Reto 10 (Implementación de Defensa Perimetral - Evidencia AE 2.1.1): Presenta el reporte técnico de implementación con topología, scripts probados y capturas de paquetes para el 25% SAE (Heteroevaluación).
